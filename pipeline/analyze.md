# analyze.md —— 人物分析任务书（opencode 专用）

> 用户说「分析张三」「分析全部」或类似指令时，按本任务书执行。
> 维度定义与打分规则见 `docs/分析维度说明.md`。

## 一、触发与目标

| 触发 | 目标 |
|---|---|
| `分析张三` | 对**单个人物**运行完整分析 → 更新 `data/people/<ref>.md` |
| `分析全部` | 遍历 `register.json` 中记忆数有变化的人物，逐人执行上面的流程 |
| `录入 ...` | 接收用户粘贴/指名的记忆 JSON → 交给 `pipeline/helpers/ingest.py`（照其用法），成功后可选再分析 |

## 二、执行步骤（顺序执行，缺一不可）

1. **读别名表** `data/aliases.md` → 锁定 ref，把人名归一化（别名并入，新名字判断是新建还是合并）；
2. **读索引** `data/meta/register.json` → 拿到该人物全部记忆的 `m序号 ↔ id ↔ date` 映射；
3. **读旧档案** `data/people/<ref>.md`（若存在）→ 作为旧结论上下文；
4. **读记忆** `data/memories/**/<id>.json` → 按 `created_at` 排序，作为新证据；**只读 `memories/`，永远不读 `data/private/`**；
5. **校验与矛盾识别**：
   - 过滤"把推断当事实"的记录（对照 subject/evaluation 文本）；
   - 识别与旧结论冲突的新证据（时间近 3 个月优先）；
6. **归纳**：按 §三 维度产出性格画像、应对策略、变化趋势（含置信度）；
7. **写档**：套用 §四 模板写 `data/people/<ref>.md`，每条结论标注 `[m序号]`；
8. **重算索引**：运行 `python pipeline/helpers/ingest.py --reindex`（register 是生成物，**永不手改**）；
9. **提交建议**：给用户 `git add` + `analysis:` 提交建议，**不自动 commit**。

## 三、分析维度（打分规则见 docs/分析维度说明.md）

- 大五人格（开放性/尽责性/外向性/宜人性/神经质，1-5）
- 沟通风格（直接度/信息密度/寒暄偏好/修辞习惯）
- 决策模式（风险偏好/信息依赖/决策速度）
- 冲突处理（正面/回避/转移 + 压力反应）
- 情绪特点（稳定性/表达度/压力反应）
- 合作价值（可依赖度/需补位点）

## 四、人物档案模板（data/people/<ref>.md 必须遵守）

```markdown
# 人物档案：{{真名}}

## 基本信息
- ref: <ref>   relation: <关系>   首次记录: <YYYY-MM-DD>
- 真名: <真名>    假名: <假名>（仅展示层使用）
- 记忆数: N 条    最近互动: <YYYY-MM-DD>

## 性格画像（updated: <日期>, 证据索引: [m..]）
- 大五人格: 开放性 x / 尽责性 x / 外向性 x / 宜人性 x / 神经质 x
- 沟通风格: …
- 决策模式: …
- 冲突处理: …
- 情绪特点: …

> 置信度说明：高=≥3 条一致证据 / 中=2 条 / 低=1 条或推断。推断用 🧊 标注 + 置信度。

## 应对策略（updated: <日期>）
- 沟通: …（≤1 行）
- 合作: …
- 汇报: …
- 边界: …

## 行为变化趋势
- <时间节点>: 旧→新 变化及可能的诱因；无证据则写"样本有限，暂不标注趋势"

## 待跟进
- <来自 follow_up / 上一轮遗留>

> 证据引用规则：每条结论后标 [m序号]；旧结论与新证据冲突时，以近 3 个月记忆为准，并在此标注"行为模式发生转变"。
```

## 五、结论规范（克制）

- **事实与推断分离**：能落到"某条记忆里确实发生了什么"的 → 事实（带 m 证据）；推测其性格/动机的 → `🧊 推断` + 置信度；
- **克制**：单次分析 = 1 句总结（放基本信息下方或画像首行）+ 3-5 个关键标签 + 每条策略 ≤ 1 行；
- **转变标注**：与旧结论冲突时不删旧结论，追加时间轴变化；
- **样本不足**：该人物记忆 < 3 条时，档案顶部明示"样本有限，结论置信度低，需积累后复核"。

## 六、红线（违反即视为失败）

1. 不手工编辑 `register.json`（只能 `ingest.py --reindex`）；
2. 不读取/引用 `data/private/` 与 `-PRIVATE.json` 的任何内容；
3. 提交信息只用 ref/假名，禁止真名；
4. 不把推断写成事实、不给无证据的维度强行打分；
5. 不自动 commit，只给建议等用户确认。
